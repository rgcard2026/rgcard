# RG-Card v3.9.27 — Mobile UX, New Arrival Manager, and WhatsApp Security Alerts

## New Arrival / Coming Soon

- The user-facing banner is **logo-only**: no discount, branch, description, or place name is rendered inside the banner.
- The banner is a continuously moving, seamless carousel for every number of selected places, including one or two items.
- The public banner reads the existing `Place.isFeatured`, `Place.sortOrder`, and `Place.isActive` fields, so no database migration is required.
- A separate admin page is available at `/admin/new-arrivals`.
  - Add active places to the banner.
  - Remove places from the banner.
  - Move each selected place up or down to control the sequence.
  - The first item is the first item in the banner movement.
- Banner controls were removed from the regular places-and-offers workflow. CSV imports no longer activate banner visibility; use the dedicated New Arrival page after import.

## Mobile user experience

- The offers page uses a compact mobile header and banner.
- Offer/place cards render as clear two-column cards on small phones, with the complete logo and place name only.
- Touch targets for filters, banner logos, cards, and pagination remain comfortably tappable.
- Medium-size phones/tablets transition to three columns, while desktop keeps a fluid grid.

## WhatsApp security alerts

The project can send a security alert payload to a webhook. Connect that webhook to an official WhatsApp delivery method, such as a Meta Cloud API, Twilio, n8n, or Make flow.

1. Configure these environment variables in `.env` or Railway:

```env
SECURITY_ALERT_WEBHOOK_URL="https://your-webhook.example/rg-card-security-alert"
SECURITY_ALERT_WEBHOOK_TOKEN="optional-shared-secret"
SECURITY_ALERT_TIMEOUT_MS="6000"
TZ="Africa/Cairo"
```

2. Restart the project.
3. In the admin dashboard, open **التنبيهات الأمنية**.
4. Enable alerts, set the cooldown, save, and send a test message.

The alert message includes only the event type, severity, source IP, route, and timestamp. It intentionally excludes passwords, full request bodies, card numbers, ID numbers, and hashes.

Alerted events include suspicious blocked requests, repeated failed user/admin login activity, brute-force account blocks, and encrypted payload failures.
